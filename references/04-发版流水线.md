# 04 · 发版流水线（CLI 一键部署）

> 目标：把"控制台手动传 zip"升级为 `bash scripts/deploy-cloud.sh "备注"` 一条命令发版。

## 4.1 一次性准备

### ① 安装 CLI（版本必须 2.x）

```bash
npm i -g @wxcloud/cli@2.3.3 --registry=https://registry.npmmirror.com
wxcloud --version   # 应输出 2.3.3
```

> **实测**：1.1.8 版本没有 `run:deploy` 命令，且**不读 `.dockerignore`**（会把 .env 一起打包上传！）。务必使用 2.x。

### ② 生成 CLI 私钥

控制台 → 云托管 → 设置 → 全局设置 → **CLI 密钥** → 生成并下载私钥文件。

**密钥保管铁律**：
- 存到仓库**外面**的路径（如 `$HOME/wxcloud-key.txt`），并在 `.gitignore` 加 `*wxcloud-key*`、`*.pem`
- 脚本里用 `-k "$(tr -d '\r' < "$KEY_FILE")"` 注入，**不回显、不进日志、不进历史命令**
- 下载后注意 Windows 记事本可能存成 `.txt.txt` 双后缀，检查文件名

### ③ 首次登录

```bash
wxcloud login -a <AppID> -k "$(tr -d '\r' < /path/to/key.txt)"
# 凭据会存到 ~/.wxcloudconfig；换密钥时先 wxcloud logout
```

## 4.2 部署脚本原理（三段式）

完整模板见 `templates/deploy-cloud.sh`，核心就三段：

```bash
# 1) 重建「白名单暂存目录」——只复制该上传的文件
#    （比"排除黑名单"更安全：.env/node_modules/data 物理不存在于暂存目录）
#    ⚠ 白名单目录会整目录拷：scripts/ 里的冒烟中间产物（req.json 等）也会进包——
#      保持 scripts/ 干净，或把这一行改成逐文件列举
rm -rf "$STAGING" && mkdir -p "$STAGING"
cp -r package.json tsconfig.json src scripts Dockerfile .dockerignore "$STAGING/"

# 2) 在暂存目录里打包上传
cd "$STAGING"
wxcloud run:deploy . \
  -e "$ENV_ID" -s "$SERVICE" --region "ap-shanghai" \
  --targetDir . --dockerfile Dockerfile --containerPort 3000 \
  --releaseType FULL --noConfirm \
  --remark "${1:-cli 部署 $(date +%m%d-%H%M)}"

# 3) 解释输出：等 "check_build_image : succ" + "部署<服务名>-<版本>"
```

**双保险设计**：白名单暂存（第一道）+ `.dockerignore`（第二道，防 CLI 行为变化）。

**模板默认路径（跨盘符安全）**：私钥 `$HOME/wxcloud-key.txt`、暂存 `$HOME/<你的项目>-deploy-src`——不要写死 D 盘等固定盘符；可用环境变量 `WXCLOUD_KEY_FILE` / `WXCLOUD_STAGING` 覆盖。

**`.dockerignore` 最小内容**：

```
node_modules
data
.env
.env.*
*.zip
*.log
docker-compose.yml
```

## 4.3 日常发版流程

```bash
# 改完代码：
cd server && npx tsc --noEmit        # 1) 类型检查（真 tsc！）
bash scripts/deploy-cloud.sh "这次改了什么"   # 2) 发版
# 3) 等 1-3 分钟构建，控制台看实例状态；首次启动等 MySQL 唤醒多等 ~1 分钟
```

**版本号规则**：服务名-序号-时间戳（如 `myapp-api-010-20261009223758`），序号自动递增，可用于回滚定位。

## 4.4 输出解读与故障排查

| 输出 | 含义 |
|---|---|
| `check_build_image : succ` | 镜像构建成功 |
| `部署<服务名>-<版本>` | 已触发发布，实例滚动更新 |
| `ResourceNotFound.TopicNotExist` | **无害噪音**（CLI 拉日志主题不存在），不影响部署 |
| `Failed to connect...` | 网络问题，重试或检查代理 |
| 实例一直"启动中" | 首启等 MySQL/依赖；超过 5 分钟看控制台日志 |

**回滚**：控制台版本管理里选中历史版本批量回滚，或 `wxcloud run:rollback`。
