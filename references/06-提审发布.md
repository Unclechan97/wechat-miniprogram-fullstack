# 06 · 提审与发布

## 6.1 ★ 命名规则（最容易翻车的一关）

**实测被拒理由**："你申请的名称涉及以通用词命名，故审核不通过" —— 名称含行业通用词（如"记账""助手""查询""服务""工具"）且无商标时，审核会拒。

**规则**：
- 名称不能以**通用词**为核心（"记账""记账本""小助手"类都不行）
- 改名机会有限（**每年 2 次**，以官方最新规则为准）——别浪费在裸通用词组合上
- 有《商标注册证》可压住含商标词的名称
- 名称里有品牌/生造词 + 功能词的组合通过率最高

**造名法**：「特色词（2 字）+ 功能词」或「意象词 + 账/夹/本」。示例（记账产品）：
- 拾光小账本、云雀账夹、山茶小记

**操作**：后台 → 设置 → 基本设置 → 小程序名称 → 修改。名称框会实时提示可用性，**在保留下来的次数里挑能用的**。

补充规则（对抗性校验时的官方资料）：个人主体**发布后**每自然年 2 次免费改名（1 月 1 日重置）；未发布前共 3 次机会（注册占 1 次）；名称 4~30 字符；命中品牌保护词需资质审核（约 7 个工作日）；企业主体改名需先微信认证（300 元）。

> 顺带：名称过审后，体验版/正式版显示的名称自动更新；代码审核与名称审核可以并行提交，但建议**名称先过再发布**。
> ⚠️ **改名与备案联动**：ICP 备案信息需与小程序名称一致，**改名后要同步更新备案**，否则可能审核异常。所以最好在备案之前就把名字定稿。

## 6.2 类目设置

- 位置：设置 → 基本设置 → 服务类目
- 原则：**与功能严格匹配**（提审被拒常见原因就是类目不符）
- 个人主体可选范围有限，一般落在**工具**大类下。功能 → 类目速查（示例，**最终以控制台实时可选列表为准**）：

| 功能形态 | 常用类目 |
|---|---|
| 记账 / 打卡 / 习惯养成 / 待办 | 工具 > 效率（或"信息查询"） |
| 信息展示 / 查询工具 | 工具 > 信息查询 |
| 健康习惯记录（步行/喝水/服药提醒） | 工具 > 效率 / 信息查询（"健康"大类多需资质，个人慎选） |

- 拿不准就选"覆盖面最贴切"的工具子类；类目和名称一起提前提交（修改也要审核）

## 6.3 提交审核

**位置**：mp 后台 → 管理 → 版本管理 → 开发版本 → 提交审核

**填写模板**：

| 字段 | 内容 |
|---|---|
| 功能页面 | 主页路径，如 `pages/index/index` |
| 测试账号 | 无需登录的写"无需（打开即用）"；有登录的必须给测试账号 |
| 审核备注 | 见下方模板 |

**审核备注模板**（把功能/权限/测试路径说清楚，减少被拒）：

```
本小程序为XX工具，无需登录，打开即用。
语音功能需麦克风权限，请在真机上点击XX按钮授权后测试；
拍照功能需相机/相册权限。
[如有特殊功能] XX功能通过首页XX入口进入，另一账号XX后可测试（只读）。
```

**提审前清理**：
- [ ] 删除调试代码（如异常文件落盘、测试按钮、console 噪音）
- [ ] 确认无硬编码测试数据/后门接口
- [ ] 服务端保持在线（审核员会真实访问）
- [ ] 隐私声明：有隐私接口 → 指引已配且与调用一致；**无隐私接口 → 勾选「未采集用户隐私」**（否则会被拦，见 05 §5.2）

## 6.4 审核与发布

| 阶段 | 时长 | 注意 |
|---|---|---|
| 代码审核 | 一般 1-2 天（可加急） | 驳回后改完可重新提交，记下驳回理由对症改 |
| 发布 | 审核通过后手动点 | 版本管理页面出现「发布」按钮 |
| 灰度 | 可选 | 全量或按比例 |

**发布后**：
- 确认线上实例稳定（控制台 + 真实访问一遍）
- 保留体验版通道用于后续灰度测试
- 正式版会**强制域名校验**——如果依赖直连通道，必须先有备案域名（云托管默认域名不可用），否则只能走 callContainer

## 6.5 常见驳回原因速查

| 驳回理由 | 对策 |
|---|---|
| 名称含通用词 | 按 6.1 换名 |
| 类目与功能不符 | 调整类目（宁可选更贴切的小类） |
| 功能不完整/白屏 | 检查审核员环境（正式版域名校验！callContainer 是否可用、后端是否在线） |
| 隐私指引缺失/不符 | 补全指引且与实际调用一致 |
| 涉及未开放能力 | 检查主体类型（个人 vs 企业）能用什么 |
