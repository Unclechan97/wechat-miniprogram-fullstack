# 07 · 踩坑大全（按现象查）

> 全部为真实发生并解决的坑。格式：**现象 → 根因 → 解法**。

## A. 环境与工具链

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| A1 | `npx tsc --noEmit` 打印 "This is not the tsc command you are looking for" **且 exit 0** | 在无本地 typescript 的目录跑 npx，拉到了恶搞包 | 确认 devDeps 有真 typescript；`cd 项目目录 && npx tsc --noEmit` 一条命令内完成 |
| A2 | 服务端类型错误没报，运行时字段静默 undefined | tsx 直接跑 TS，**不做类型检查** | 每次改完单独跑 tsc；关键字段加运行时断言 |
| A3 | Git Bash 里 curl 发中文，入库变乱码 | 终端编码 GBK | `--data-binary @utf8.json`；验证看响应 hex |
| A4 | node 请求 `localhost` 报 502/连接异常 | node24 undici 把 localhost 解析成 IPv6，被系统代理拦 | 一律 `127.0.0.1` |
| A5 | node 读 `/tmp/xxx` 文件不存在 | Git Bash 的 /tmp ≠ Windows 路径 | `cygpath -m` 转换或写项目内路径 |
| A6 | `npm config set` 下划线键被 npm11 拒绝 | npm 新版本校验 | 用 `npm_config_*` 环境变量传（Dockerfile 里同理） |
| A7 | 下载的密钥文件名叫 `xxx.txt.txt` | Windows 记事本自动加后缀 | 改名后 `file` 命令/看大小验证 |
| A8 | `TZ=Asia/Shanghai npx tsx ...` 启动后 `process.env.TZ === undefined`，**无任何报错** | Windows 下 TZ 被特殊对待，Git Bash 内联/export 都传不进 Node；本机恰在东八区时"看起来对" | 本地用 `cmd //c "set TZ=...&& ..."`，或日期逻辑用显式 +8 偏移（`todayInCST()`，见 02 §2.1）；容器内 ENV TZ 实测生效 |
| A9 | AI/CI 或无 GUI 环境：新建工程、上传代码无从下手 | 默认路径全靠工具 GUI | 工程骨架手写（`templates/miniprogram-scaffold/`，含 useCompilerPlugins 等关键字段）；上传用工具自带 CLI（`cli.bat upload`，需开服务端口），见 01 §1.2 / 05 §5.1 |

## B. 微信平台 / 账号

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| B1 | 个人主体添加插件被拒（如 WechatSI） | 插件要求特定类目，个人无 | 自建链路（录音+云 ASR），见 SKILL 决策 1 |
| B2 | 云托管默认域名无法加入"服务器域名" | 平台规定其仅测试用 | 正式版纯 callContainer 或自有备案域名 |
| B3 | 改名被拒："涉及以通用词命名" | "记账/助手"等通用词无商标 | 特色词+功能词命名，见 06-提审发布 |
| B4 | 真机隐私接口无反应，工具正常 | 隐私保护指引未收录该信息类型 | 后台配置并收录麦克风/相册/摄像头，见 05 |
| B5 | 摄像头接口被拒，但"相册"已经配了 | `chooseMedia` camera 模式算**摄像头**，须单独收录 | 隐私指引"增加信息类型"补摄像头 |
| B6 | 体验版普通用户搜不到 | 体验版仅体验成员可用 | 成员管理加人；要公开必须正式发布 |
| B7 | 缩零后第一次请求等十几秒甚至失败 | 云托管默认缩容到 0 | 最小实例数设为 1 |
| B8 | 没用到任何隐私接口，提交审核却因隐私声明被拦 | 无隐私接口 ≠ 不用管 | 提审页勾选/声明「未采集用户隐私」（见 05 §5.2 / 06 §6.3） |
| B9 | 以为用了云托管/没买域名就"不用备案" | "免域名免备案"免的是**域名/服务器侧**；小程序**自身**必须完成 ICP 备案（法规要求，与后端放哪无关） | 尽早办（免费，1-3 周；入口见 01）；存量小程序有截止日（后台显示，到期未备案将无法打开）；先定名再备案（改名需同步变更备案，见 06） |

## C. 网络与请求（最费时间的一类）

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| C1 | `cloud.callContainer:fail -606001 system error`，突发、恢复后正常、容器日志无记录 | **网关层拒绝，请求未到容器**；容器 CPU 打满或大包体是诱因 | 直连压测对照判定归属（03-3.3）；解法：1核2G / 减请求 / 重试+幂等 / 直连通道 |
| C2 | callContainer 传文件报错/不支持 | 网关不支持 multipart | JSON base64；≤3MB（express.json limit） |
| C3 | 大图上传报 -606001 | base64 后 2-3MB 超网关包体上限 | `wx.compressImage` 压到 ≤1.2MB（长边 1280/质量 60，超了再压一轮） |
| C4 | 真机提示"未授权访问"（服务端返回） | 直连被域名校验拦→回退 callContainer→**回退通道请求头漏了密钥** | 统一请求头构造函数，所有通道都带（03-3.4） |
| C5 | 网关报错后用户看到失败，但稍后重试能成功 | 无重试机制 | `gatewayRetry` 2s/6s/12s 梯度，仅对网关类错误 |
| C6 | 重试/双击导致重复入账 | 无幂等 | 写接口 `client_token` 幂等键 + 服务端查重 |
| C7 | 频繁小请求易触发网关异常 | 每次业务多次网关调用 | 合并响应（ASR 响应捎带解析结果、保存响应捎带汇总），一次录音 5→2 次调用 |
| C8 | 云托管 MySQL 报 "instance is resuming"/ECONNREFUSED | serverless 10 分钟无连接自动暂停 | 数据层对瞬时错误自动重试 ≤33s；首启 initDb 成功才 listen |
| C9 | DIRECT_BASE 直连在开发者工具好了，真机没生效 | 体验版/正式版强制域名校验（云托管域名加不进白名单）；工具勾选只在工具内生效 | 依赖回退通道；或自有备案域名；真机 http 明文需手机端开调试（正式版无解） |
| C10 | callContainer 报"环境不存在/云能力未初始化"类错误 | 前置条件缺失：没 `wx.cloud.init` / 基础库 <2.23.0 / 小程序未与云托管环境关联 | 三件套补齐（见 03 §3.2）；**别误判成 -606001 去瞎调规格** |

## D. 音频与媒体

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| D1 | 真机没声音/工具正常 | iOS 静音开关（默认遵循） | `audio.obeyMuteSwitch = false`；排查顺序：播报开关→静音键→媒体音量 |
| D2 | "报错后播报上一条"的诡异串音 | 工具对同路径音频文件有解码缓存 | 每次写唯一文件名 `tts-<时间戳>.mp3`；播完删旧文件 |
| D3 | 录音按钮偶发无反应（无 onStart 无 onError） | RecorderManager.start() 偶发卡死（工具更多见） | 1.5s 看门狗：stop() 后重试一次；仍失败给"按钮没反应，请再试一次"文案 |
| D4 | 工具录的音频在真机/客户端播不了 | 开发者工具录音格式与移动端不同（官方说明） | 工具录音仅工具内调试；判断音质问题用真机 |
| D5 | 识别引擎不认小程序录音格式 | 录音格式五花八门 | 服务端 ffmpeg 统一归一化 16k 单声道 wav 再喂识别 |
| D6 | 误触一下（<1s）发起无效识别 | 无防误触 | duration < 1000ms 提示"按住说话，说完再松开" |

## E. 部署与运维

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| E1 | CLI 没有 `run:deploy` 命令 | 装的 1.1.8 旧版 | 升到 2.x（1.x 还**不读 .dockerignore**，会传 .env！） |
| E2 | 部署输出一堆 `ResourceNotFound.TopicNotExist` | CLI 拉日志主题的噪音 | 无害，无视 |
| E3 | 担心 .env 被打包上传 | 默认打包行为不可靠 | 白名单暂存目录（.env 物理不在）+ .dockerignore 双保险 |
| E4 | 私钥明文出现在日志/历史里 | 直接内联 | `"$(tr -d '\r' < "$KEY_FILE")"` 注入；文件放仓库外 + gitignore |
| E5 | Docker 构建 apt-get 卡死 | deb.debian.org 国内直连极慢 | 换清华源（Dockerfile 模板已处理） |
| E6 | 微信云托管 CLI 查不了日志/实例状态 | CLI 只有 deploy/rollback/service 命令 | 排障走公网域名 curl + 控制台面板 |
| E7 | `wxcloud service:config read` 把密钥全打印出来 | CLI 行为（envParams 原样输出） | 调用时过滤输出（`grep -v envParams`）；截图注意别带 |
| E8 | 宿主机 3306 被本机 MySQL 占用 | 端口冲突 | compose 映射 "33061:3306"；**33061 也可能被别的容器占**——顺延 33062/33063，端口一处改 |
| E9 | `docker compose up` 可能接管/重建**别人项目**的容器 | compose 默认拿目录名当项目名，compose 文件在 `server/` 时项目名就是 "server"，同机撞名 | 启动固定 `-p <项目名>`，或用模板顶层 `name:`（见 templates/docker-compose.yml） |
| E10 | compose 里容器"起了但连不上库/外部访问不到" | `env_file: .env` 把宿主视角配置原样塞进容器：`MYSQL_HOST=127.0.0.1:33061` 容器里连自己（ECONNREFUSED，还被重试吞 33 秒）；`PORT=3001` 与映射 3000:3000 错位 | `environment:` 显式覆盖 `MYSQL_HOST: mysql:3306`、`PORT: "3000"`（优先级高于 env_file；模板已内置） |
| E11 | 云服务器/容器上开了公网访问后，身份可被伪造 | `x-wx-openid` 头外部可自行伪造 | 身份端点只走 callContainer；模拟身份开关 `ALLOW_MOCK_IDENTITY` 生产必须 false（见 03 §3.4） |

## F. 数据层

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| F1 | 金额计算出现 0.1+0.2 类误差 | 浮点存储 | 整数分存储（BIGINT），展示层转换 |
| F2 | 表结构升级要停机 | 直接 DROP/重建 | **幂等 ALTER 平滑升级**：启动时逐条 ALTER，捕获 Duplicate column/key 类错误忽略，其余抛出 |
| F3 | 中文存进去变问号 | 连接字符集不是 utf8mb4 | 连接参数显式 utf8mb4；验证用 hex 检查而不是肉眼看 |
| F4 | fetch 读到的文本开头 BOM 神秘消失 | WHATWG 规范剥离 BOM | 需要验证 BOM 时看 arrayBuffer 原始字节 |
| F5 | 云 MySQL 首连失败进程退出 | 没等唤醒 | initDb 带重试；成功才 listen |
| F6 | 数据模型没有文本字段，"中文写入 hex 校验"验收无处落 | 验收清单按记账模型写的 | 变通：中文错误响应的 hex 校验 + 会话级临时表做写入→读回 hex 往返（`SHOW VARIABLES` 确认 utf8mb4） |
