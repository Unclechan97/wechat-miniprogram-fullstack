# 02 · 本地联调

## 2.1 服务端本地运行

```bash
cd server
cp <skill路径>/references/templates/env.example .env   # 变量清单与说明见文件内注释（改值直接编辑 .env）
npx tsx src/app.ts        # 或 npm run dev（tsx watch）
```

**config.ts 模式**：所有环境变量在一个文件集中读取，带默认值兜底：

```ts
import 'dotenv/config';

export const config = {
  port: Number(process.env.PORT || 3000),
  zhipuApiKey: process.env.ZHIPU_API_KEY || '',
  mysqlHost: (process.env.MYSQL_HOST || '127.0.0.1').split(':')[0],
  mysqlPort: Number((process.env.MYSQL_HOST || '').split(':')[1] || process.env.MYSQL_PORT || 3306),
  // 兼容把控制台 "host:port" 整串直接贴进 MYSQL_HOST 的情况
  appSharedKey: process.env.APP_SHARED_KEY || '',                    // 开放端点共享密钥（见 03 §3.4）
  allowMockIdentity: process.env.ALLOW_MOCK_IDENTITY === 'true',     // ★ 生产必须 false！
};
```

**身份解析（与服务端配对，安全关键）**：

```ts
// server/src/utils/identity.ts —— 本地开发信任 X-User-Id，生产只认网关注入的 openid
const openid = req.header('x-wx-openid');          // callContainer 网关注入，不可伪造
if (openid) return openid;
if (config.allowMockIdentity) {
  const mock = req.header('x-user-id');            // 仅本地 .env 开 ALLOW_MOCK_IDENTITY=true 时生效
  if (mock) return mock;
}
return null;                                        // 没有身份 → 401
```

**数据层模式（mysql2）**：包一层 `db.get / db.all / db.run`，对"休眠唤醒"类瞬时错误自动重试：

```ts
const RETRY_DELAYS = [500, 1500, 3000, 5000, 5000, 8000, 10000]; // ≈33s
const TRANSIENT_RE = /resuming|ECONNREFUSED|ETIMEDOUT|ECONNRESET|EPIPE|PROTOCOL_CONNECTION_LOST/i;
```

**启动顺序**：`initDb()` 成功后才 `app.listen()`——建表/迁移没完成时不要对外服务。

### ★ Windows 本地 TZ 陷阱（实测，必读）

Git Bash 里内联 `TZ=Asia/Shanghai npx tsx src/app.ts` **不会传进 Node**（进程里 `process.env.TZ === undefined`，**且无任何报错**；`env TZ=...` 写法同样失效——TZ 被 Windows 特殊对待）。本机恰好在东八区时"看起来对"，换机器/CI 就静默算错日期。两种解法：

```bash
# ① 用 cmd 包一层（本地临时排查用）
cmd //c "set TZ=Asia/Shanghai&& npx tsx src/app.ts"
```

```ts
// ② 更稳：日期边界不依赖 TZ，代码里显式按东八区算
export function todayInCST(): string {
  const d = new Date(Date.now() + 8 * 3600 * 1000);
  return d.toISOString().slice(0, 10);   // YYYY-MM-DD（东八区）
}
```

验证方法：让 `/health` 返回 `tz`/`today` 字段，一眼看出时区是否按预期生效。容器里 `ENV TZ=Asia/Shanghai` 是**生效的**（实测），云上不受此坑影响。

## 2.2 本地数据库（Docker Compose）

```bash
# ★ 必须带项目名启动（或用模板顶层 name:）——compose 默认拿【目录名】当项目名，
#   compose 文件放在 server/ 目录时项目名就是 "server"，同机别的项目若也有 server/
#   目录会撞名，up 时可能接管/重建别人的容器（真实踩坑）！
docker compose -p myapp up -d
```

**三个必读坑（模板 `templates/docker-compose.yml` 已全部处理）**：

| 坑 | 现象 | 解法 |
|---|---|---|
| **端口** | 宿主 3306 常被本机 MySQL 占 → 映射 33061；**33061 也可能被别的容器占** | 顺延 33062/33063，端口只在 `.env`/compose 一处改 |
| **env_file 视角错位** | `env_file: .env` 把宿主视角配置原样塞进容器：`.env` 的 `MYSQL_HOST=127.0.0.1:33061` → 容器里"连自己" → ECONNREFUSED（还被重试逻辑吞 33 秒）；`.env` 的 `PORT=3001` → 容器监听 3001 而映射 3000 → **容器正常但访问不到** | 用 `environment:` 显式覆盖 `MYSQL_HOST: mysql:3306`、`PORT: "3000"`（environment 优先级高于 env_file） |
| **库名不同步** | mysql 容器硬编码建 `myapp`，而 app 按 `.env` 连别的库名 → `ER_BAD_DB_ERROR` crash-loop | 模板已改 `${MYSQL_DATABASE:-myapp}` 与 `.env` 同步；⚠️ **已存在的卷不补建新库**——换库名需手动 `CREATE DATABASE` 或 `docker compose down -v`（清数据） |
| **项目名撞车** | 见上，可能动到别人容器 | 固定 `-p <项目名>` 或 compose 顶层 `name:` |

**Docker 没装/没启动怎么办**：先启动 Docker Desktop（`"C:\Program Files\Docker\Docker\Docker Desktop.exe" &`，等 `docker info` 有输出）。没有 Docker 但本机已装 MySQL：直接在它上面建库建用户，连接信息写进 `.env`，效果等价。

> 完整（已修正上述三点）见 `templates/docker-compose.yml`。

**Dockerfile 要点**：
- 国内必须换 apt 源（清华），否则 `apt-get update` 卡 10 分钟+
- `ENV npm_config_registry=https://registry.npmmirror.com` 加速 npm install
- `ENV TZ=Asia/Shanghai` 固定时区
- 需要 ffmpeg 等二进制时在镜像里装，不要依赖宿主

## 2.3 curl 冒烟三大坑（Windows Git Bash）

| 坑 | 现象 | 解法 |
|---|---|---|
| **中文变 GBK** | 命令行内联中文 POST 后库里乱码 | `--data-binary @req.json`，文件用编辑器确认为 UTF-8；判断是否乱码看响应 hex |
| **localhost 解析到 IPv6** | node 24/undici 请求 localhost 被系统代理拦成 502 | 一律用 `127.0.0.1` |
| **/tmp 路径不通** | Git Bash 的 /tmp 与 Windows 路径不一致，node 读不到文件 | `cygpath -m /tmp` 转换，或直接写项目内路径 |

冒烟标准动作：

```bash
curl http://127.0.0.1:3000/health
curl http://127.0.0.1:3000/api/categories
# 写接口用文件体：
curl -X POST http://127.0.0.1:3000/api/transactions \
  -H 'content-type: application/json' --data-binary @req.json
```

## 2.4 开发者工具联调

1. 导入 `miniprogram/` 目录（AppID 填你的；**游客模式/测试号不能用云能力（callContainer）**，本地 local 模式不受影响）
2. **详情 → 本地设置 → 勾选「不校验合法域名」**（本地 API_MODE=local 时必需；用云托管直连调试时也必需）。
   文件等价物：`project.config.json` 里 `"setting": { "urlCheck": false }`（手写骨架已含）
3. `utils/config.ts` 的 `BASE_URL` 指到 `http://127.0.0.1:3000`
4. 真机预览：`BASE_URL` 改成电脑局域网 IP（`ipconfig` 查），手机与电脑同一 WiFi，**并给 Windows 防火墙放行该端口**（不放行 = 手机连不上，报网络错误）
   > 注意：工具里勾"不校验合法域名"**只在工具内生效**；真机规则见 05 §5.3（云托管项目按决策 3 走 callContainer 即可绕开）

## 2.5 本地全链路验收

- [ ] 每个路由至少 curl 冒烟一次
- [ ] 中文不乱码验证（**数据模型没有文本字段时**：用中文错误响应的 hex 校验 + 会话级临时表 hex 往返，见 07-F6）
- [ ] 重启服务后数据仍在（排除内存态假持久化）
- [ ] 写接口幂等验证：同一 `client_token` 提交两次 → **业务量不变**（金额/杯数/条数不重复累加）。

  ```bash
  curl -X POST http://127.0.0.1:3000/api/records -H 'content-type: application/json' \
    -H 'X-User-Id: u-test' --data-binary @once.json      # 第一次
  curl -X POST http://127.0.0.1:3000/api/records -H 'content-type: application/json' \
    -H 'X-User-Id: u-test' --data-binary @once.json      # 第二次：业务量应不变
  ```

  ⚠️ 断言要盯**业务量**，不要盯整包响应：若响应里带 `duplicated` 标记、时间戳等，"两次响应完全一致"的断言会**假失败**。
- [ ] 时间边界：`今天/本月` 汇总与数据库手查一致；`/health` 里的 `tz`/`today` 字段正确（Windows 本地注意 TZ 陷阱，见 2.1）
- [ ] 双端 tsc 真通过

> 顺序建议：**本地上把业务逻辑全部跑通再上云**。云上的问题应该只剩"环境差异"，不应该是"逻辑没测"。
