# 01 · 启动与骨架

## 1.1 账号准备清单

| 事项 | 说明 |
|---|---|
| AppID | mp.weixin.qq.com → 立即注册小程序：邮箱（从未注册过公众号/小程序的）→ 选主体（个人：身份证 + 微信扫脸实名）→ **免费，约 10 分钟**拿到 AppID。也可复用已有小程序（个人主体可复用已发布的旧号，改名+改类目即可）。**没有 AppID 也能先开发**（工具测试号/游客模式），但**云能力（callContainer）必须正式 AppID** |
| ICP 备案 | **新注册的小程序必须先完成备案才能上架**（约 1-2 周）。入口：mp 后台 → 设置 → 基本设置 → 小程序备案，按页面指引提交（个人：身份证 + 人脸核验；需填服务内容类型、应急联系人）。老号检查备案状态即可 |
| 类目 | 发布前设置，**必须与功能匹配**；个人主体可选范围以控制台「设置→基本设置→服务类目→添加」实时列表为准（一般落在工具大类下） |
| 服务器域名 | 用 callContainer 则**不需要**配域名；若走公网直连/自建后端则需要（云托管默认域名 **不允许** 加入合法域名，仅限测试） |
| 隐私保护指引 | 用任何隐私接口（麦克风/相册/摄像头/位置）前必须配置，否则**真机直接拒绝**（详见 05）。**没用隐私接口≠不用管**：提审时要声明「未采集用户隐私」（见 06 §6.3） |

> 实测坑：云托管默认域名（`*.sh.run.tcloudbase.com`）填进"服务器域名"会被拒绝："云托管域名仅用作测试使用，不可用在正式环境下"。正式版要么纯 callContainer，要么自有备案域名。

## 1.2 装机清单（Windows）

```bash
# Node.js LTS（>=20）
node -v

# 微信开发者工具：https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html 下载稳定版
# 可选：Docker Desktop（本地跑数据库/服务用）

# npm 走国内镜像（全局）
npm config set registry https://registry.npmmirror.com
```

**新建项目（两条路，任选）**：

- **有 GUI**：开发者工具 → 新建项目 → 选 **「不使用云服务 + TypeScript」模板**（自动生成 tsconfig 与 typings）。
  > 注意：「不使用云服务」只是不启用"云开发框架"，`wx.cloud.*`（含 callContainer）**仍可用**——但要先 `wx.cloud.init`（见 03 §3.2）。别被模板名误导成"不能用云托管"。
- **无 GUI / AI / CI**（工具开不了、或不想点）：直接手写骨架——把 `templates/miniprogram-scaffold/` 拷到 `miniprogram/`（含 `project.config.json` 的 `useCompilerPlugins`、`urlCheck` 等关键字段 + tsconfig + typings + 最小页面），照该目录 README 操作。

**工具自带 CLI**（AI/CI 上传代码的入口）：`<工具安装目录>\cli.bat upload --project <miniprogram目录> -v 1.0.0 -d "备注"`，需先在工具「设置 → 安全设置」打开服务端口（参数以官方文档为准）。

后端单独建 `server/` 目录（不进小程序目录，否则会被打包上传）。

## 1.4 双端 TypeScript 配置

**小程序端** `miniprogram/tsconfig.json`：需装 `miniprogram-api-typings`（微信 API 类型）。完整可抄版本见 `templates/miniprogram-scaffold/tsconfig.json`——**注意常见模板开 `noUnusedLocals`**：写好的函数没用上会被 tsc 直接判错（TS6133），不用的整段删掉，或 export 出去（请求层骨架模板已按此处理）。

**服务端** `server/tsconfig.json` 关键项：
```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "commonjs",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "noEmit": true
  },
  "include": ["src", "scripts"]
}
```

> **运行方式**：服务端用 `tsx src/app.ts` 直接跑 TS（不编译），享受开发效率；但 **tsx 不做类型检查**——运行时字段名/类型错误会静默变 undefined。
>
> **纪律**：每次改完服务端代码，单独跑 `cd server && npx tsc --noEmit`。

### ★ 假 tsc 陷阱（最容易骗过人的坑）

不在含有本地 typescript 的目录里跑 `npx tsc`，npm 会从registry拉一个同名恶搞包，输出：

```
This is not the tsc command you are looking for
```

**且 exit code = 0**（看起来像通过）。防法：

```bash
# 1) 确保项目有本地 typescript（devDependencies）
cd server && npm i -D typescript --registry=https://registry.npmmirror.com

# 2) 永远在同一命令里 cd 到位，防持久 cwd 漂移
cd <项目>/server && npx tsc --noEmit
cd <项目>/miniprogram && npx tsc --noEmit

# 3) 看到 "not the tsc command" 字样 = 假执行，立即停下查明原因
```

## 1.5 启动阶段的架构决定（一次到位）

| 决定 | 推荐做法 | 理由 |
|---|---|---|
| 金额存什么 | **整数分**（BIGINT），前端显示时转元 | 浮点误差在记账场景不可接受 |
| 日期存什么 | `VARCHAR(10)` 的 `YYYY-MM-DD`（本地时区字符串） | 老人视角只有"今天/昨天"，不需要时区换算；服务端设 `TZ=Asia/Shanghai` |
| 身份 | 云端：网关注入 openid 自动建档；本地：`X-User-Id` 模拟 | 一套代码两种身份源，`resolveUserId` 统一 |
| 幂等 | 写接口带 `client_token`，服务端查重 | 移动网络重试/老人双击防重复入账 |
| 时区 | 容器 `ENV TZ=Asia/Shanghai`（**容器内实测生效**）；⚠️ 本地 Windows 内联 `TZ=` 不生效（实测静默失效，见 02 §2.1）→ 本地日期逻辑用显式 +8 偏移兜底 | "今天/本月"边界按东八区算 |

> **按产品形态裁剪**：金额分存储只对涉及金额的产品必要；打卡/记录类等无金额产品可跳过该项，保留**日期 / 身份 / 幂等 / 时区**四条通用项即可。
